# 基于 VLM 自然语言航点生成的无人机传统制导控制系统（阶段 1）设计规格

- 日期：2026-09-07
- 状态：已确认（待用户审查）
- 范围：阶段 1（离线一次性规划最小闭环）
- 关联模型：`b0307.mdl`（六自由度固定翼 + 制导控制律）

## 1. 背景与目标

现有系统已具备完整的传统制导控制链路：A* 避障规划 → Dubins 路径生成 → 六自由度 Simulink 仿真。本项目的核心想法是：**用自然语言驱动无人机**——操作员说一句话，视觉语言模型（VLM）将其转换为稀疏航点，交由现有传统制导控制算法执行。

本阶段（阶段 1）目标：跑通「一句话 → 一串航点 → 飞完全程」的最小闭环。

**设计原则：**

- VLM 只做上层任务翻译，不进控制环，控制稳定性由传统算法保证
- VLM 输出不可靠，校验层兜底，该校验层是独立的科研贡献点
- 现有链路一行不改，A* 保留作为对比基线

## 2. 范围与阶段规划

| 阶段 | 内容 | 状态 |
|------|------|------|
| 阶段 1 | 纯空域最小闭环：自然语言 → VLM 航点 → 校验 → Dubins → 仿真 | 本期实现 |
| 阶段 2 | 在线重规划 + 避障：飞行中自然语言干预；禁飞区提示词 + 碰撞校验 | 规划中 |
| 阶段 3 | 视觉输入（VLM 看地图）→ 真机（PX4 + Gazebo 预留） | 远期 |

**阶段 1 不包含：** 障碍物避障、飞行中重规划、视觉输入、真机部署。避障的方案已定（见第 8 节），但不在本期实现。

## 3. 总体架构与数据流

在现有链路最前端插入 VLM 航点生成器，其余全部复用：

```
[新] 自然语言指令（中文）
      ↓
[新] vlm_waypoint_planner.m   提示词构建 + 调 VLM API + JSON 解析
      ↓
[新] validate_waypoints.m     范围/间距/数量校验 + 确定性修正 + 重试
      ↓
[现有] px, py, pz → dubins_path_planning.m → fly_planfjy.mat
      ↓
[现有] init.m → b0307.mdl（六自由度 + 制导控制律）→ plotmake.m
```

航点数据格式沿用现有 `fly_pt` 约定（5 列：北向 x、东向 y、高度 z、类型、参数），高度统一取 300 m。

## 4. 组件设计

### 4.1 入口脚本 `run_vlm_mission.m`

```matlab
instruction = "从原点出发，先去(3000,4000)，再去(6500,9000)";
run_vlm_mission(instruction);
```

内部顺序：构建提示词 → 调 VLM → 校验/修正 → 生成 px、py、pz → Dubins → 存 `fly_planfjy.mat` → 跑 `init.m` + `b0307.mdl` → `plotmake.m` 出图。

### 4.2 `vlm_waypoint_planner.m`

只管「自然语言 → 结构化航点」：

1. 读入用户指令，拼装两层提示词（见 4.3）
2. 调 `call_vlm(prompt)` 获取原始输出
3. JSON 解析失败 → 附错误信息重试，最多 2 次
4. 输出 `waypoints` 数组交给校验层

### 4.3 可插拔模型接口 `call_vlm` 与配置 `api_config.m`

- `api_config.m` 集中管理：供应商、endpoint、模型名、API key（key 走环境变量或外部配置文件，不写死）
- 默认实现用 `webwrite` 走 HTTP/JSON（OpenAI 兼容接口）；预留 `py.` 桥接方案
- 换模型 = 改配置，不动业务代码；为后续多模型对比实验留好口子
- 阶段 1 实测模型待定（Qwen / DeepSeek / GPT 均可，取决于手头可用的 API）

**提示词结构（两层）：**

- **系统提示词（固定）：**
  - 角色：固定翼无人机任务规划器
  - 坐标系：x = 北向（0 ~ 10000 m），y = 东向（0 ~ 10000 m），起点固定 (0,0)
  - 约束：巡航高度固定 300 m、航点总数 ≤ 8、相邻航点间距 ≥ 200 m、航向变化平缓（照顾 Dubins 转弯半径）
- **用户指令：** 自然语言原文

**输出契约：只输出 JSON，不允许解释文字：**

```json
{"waypoints": [{"x": 0, "y": 0}, {"x": 3000, "y": 4000}, {"x": 6500, "y": 9000}]}
```

**约定：**

- z 不让 VLM 输出，高度由代码固定 300 m（缩小 VLM 输出空间）
- 起点 (0,0) 由代码强制插入，VLM 输出错误起点也会被纠正
- 温度设 0 或 0.1，保证可复现
- 单次任务只调 1 次 API（离线规划），成本与延迟可忽略

### 4.4 校验与安全层 `validate_waypoints.m`

VLM 与传统链路之间的「安检门」，全部规则确定性强、可单元测试。分三级处理：

**① 硬性检查（不通过 → 带错误信息让 VLM 重试，最多 2 次）**

| 规则 | 内容 | 不通过的后果 |
|------|------|--------------|
| 空域范围 | 0 ≤ x ≤ 10000，0 ≤ y ≤ 10000 | 重试，反馈「航点 (x,y) 超出空域」 |
| 航点数量 | 2 ≤ N ≤ 8 | 重试，反馈具体数量错误 |
| 字段合法性 | 字段齐全、数值类型正确 | 重试，附解析错误原文 |
| 相邻间距 | ≥ 200 m | 不重试，确定性修正（见下） |

**职责划分：** JSON 语法解析与重试循环统一由 `vlm_waypoint_planner.m` 负责（单一归属），`validate_waypoints.m` 只接收解析后的航点数组，负责语义规则与修正。

**② 确定性修正（代码直接改，不麻烦 VLM）：**

- 起点强制 (0,0)：删掉 VLM 给出的错误起点，前插 (0,0)
- 间距 < 200 m 的相邻点：合并/剔除较近者
- 高度：统一强制 300 m

**③ 兜底与降级：**

- 重试耗尽仍不合格 → 默认报错退出，输出人类可读的诊断报告（哪条规则、哪次重试失败）
- 开关 `use_astar_fallback`：置 1 时自动切换回现有 A* 链路，保证演示不翻车

**④ 验证报告（代码生成，不经 VLM）：**

校验层在每次修正时记一行结构化日志，例如：

```
[校验] 第1次解析失败：JSON 在第312字符处截断 → 已触发重试
[校验] 第2次输出合法
[修正] 起点 (120,80) 已强制改为 (0,0)
[修正] 航点4与航点5间距 180m < 200m → 已合并
[报告] 重试1次 | 修正2处 | 最终航点5个 | 通过
```

汇总为 `validation_report.mat` + 文本日志，形成「VLM 航点一次通过率 / 平均纠错次数 / 典型错误类型」数据，作为论文「VLM 输出可靠性分析」一节的素材。

### 4.5 复用现有链路

以下文件一行不改：

- `dubins_path_planning.m`：稀疏航点 → Dubins 可飞路径
- `init.m`、`controller.m`、`airdate.m`：载入航点与控制器增益
- `b0307.mdl`：六自由度模型 + 制导控制律（通过 Inport `fly_pt` 读取航点）
- `plotmake.m`：出图

改动仅是把 `Astar.m` 生成的 px/py 替换为 VLM 航点，A* 链路保留。

## 5. 错误处理总览

| 异常 | 处理 |
|------|------|
| API 调用失败（网络/超时） | 报错退出，提示检查 `api_config.m` |
| JSON 解析失败 | 附错误信息重试，最多 2 次 |
| 校验硬性规则不通过 | 附具体错误重试，最多 2 次 |
| 重试耗尽 | 按 `use_astar_fallback` 决定报错退出或切换 A* |
| 仿真编译/运行失败 | 冒烟测试捕获，检查 MATLAB 版本兼容性 |

## 6. 测试方案

原则：**测试不花 API 钱、可离线复现**。引入 mock VLM——把典型响应录制为固定 JSON 文件，测试时播放；真实 API 只在演示时用。

### 6.1 单元测试（MATLAB 函数式测试，`runtests`）

| 测试对象 | 用例 |
|----------|------|
| `validate_waypoints.m` 每条规则 | 越界航点、间距 < 200 m、数量超限、错误起点、JSON 解析失败→重试→耗尽报错，各一例 |
| `call_vlm` mock 模式 | 正常响应 / 截断 JSON / 超时，三种固定响应各断言一次 |
| 航点→`fly_planfjy.mat` 写入 | 格式正确（5 列、终止符行存在） |

### 6.2 集成测试（端到端，用 mock VLM）

- 固定指令 + mock 响应 → 跑完整 `run_vlm_mission` → 断言：仿真正常结束、轨迹图生成、终点误差 ≤ 阈值
- 对比脚本：同一起终点，VLM 路径 vs A* 路径，输出航程/飞行时间对比表

### 6.3 验收演示（真实 API 一次）

演示前用真实 VLM 跑一遍主场景，保留轨迹图作演示素材。

### 6.4 复现性

温度 0 + mock 响应 + 种子固定 → 实验可完全复现。

说明：`b0307.mdl` 本体一行不改，无需新增 Simulink 模型级测试，保留「能编译、能跑完」的冒烟断言即可。

## 7. 成功标准（阶段 1 验收）

1. **链路贯通：** 自然语言输入 → 仿真完整跑完 → 飞行轨迹图正确输出
2. **可飞性：** 航点经校验层处理后 100% 通过，Dubins 无解告警不出现
3. **任务达成：** 仿真终点落在目标点可接受误差内；误差阈值在实现阶段以现有 A* 链路仿真的终端误差为参照标定（相对指标，不预设绝对值）
4. **对比数据：** VLM 路径 vs A* 路径的航程、飞行时间、转弯次数可量化对比

## 8. 阶段 2 / 阶段 3 展望

### 8.1 阶段 2：避障 + 在线重规划

**避障（VLM 避障 + 传统校验兜底）：**

1. 系统提示词加禁飞区清单：障碍物定义和膨胀逻辑来自现有 `Astar.m`（障碍圆 + 1.2 倍最小转弯半径膨胀）
2. 校验层加碰撞检查规则：复用 `Astar.m` 的 `line_is_free()`，检查相邻航点连线是否穿越禁飞区，穿越则触发重试或确定性修正

**在线重规划：** Simulink 模型内加触发模块，飞行中按事件（到达航点/定时/收到新指令）调 VLM 重新规划。需处理异步调用，避免阻塞仿真步长。

### 8.2 阶段 3：视觉 + 真机

- 视觉输入：VLM 直接看机载相机/俯视地图图像（方案②），研究点最大但工程复杂度最高
- 真机：PX4 + Gazebo 软件在环，架构上 VLM 层与控制层解耦，后端可替换

## 9. 非目标（YAGNI）

- 阶段 1 不做：避障、飞行中重规划、视觉输入、VLM 自然语言任务回显、多模型对比实验框架、真机部署
- 不新增 Simulink 模型级测试
- 不重构现有 `Astar.m`、`dubins_path_planning.m`、`b0307.mdl`
